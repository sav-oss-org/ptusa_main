# Pull request style

Use this when creating or reviewing pull requests.

Follow these project rules:

- Keep one pull request focused on one concrete change.
- Put unrelated refactors, formatting, dependency updates and test
  infrastructure into separate pull requests.
- Use concise pull request titles.
- Use Markdown backticks to highlight technical words when useful, for
  example:
  ``Removes `DNS` reverse lookup from `TCP` logging``.
- Explain why the change is needed, what changed, expected risk and
  validation in the pull request body.

See `docs/CONTRIBUTING.md` and `.github/copilot-instructions.md` for the
project rules.
