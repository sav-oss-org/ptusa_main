# ptusa Lua debugger client

Windows-клиент для Lua-отладчика `ptusa_main`. Приложение подключается к
сервису 2 на TCP-порту 10000, автоматически создаёт серверную сессию и
поддерживает её периодическими запросами. Интерфейс использует тёмную тему
`qt-material`.

Возможности:

- несколько независимых вкладок для одновременной отладки разных
  контроллеров;
- дерево Lua-выражений: текущее значение и состояние в основной строке,
  предыдущее значение и статистика при раскрытии;
- настройки каждой линии в раскрытой строке: имя в легенде, цвет, сдвиг по Y
  и точки изменений; сдвиг применяется только на графике;
- тип графика для каждого выражения: ступени по переднему краю (значение
  удерживается после точки), по заднему краю (до точки), по середине интервала,
  линия или только точки; выбор применяется сразу и сохраняется в сессии;
- индивидуальный флаг «История»: графики и долговременное накопление только для
  выбранных выражений;
- единая событийная таблица истории с реальным временем (часы компьютера,
  на котором запущен отладчик) и временем контроллера (часы контроллера)
  в каждой строке, пустыми ячейками для неизменившихся выражений
  и экспортом в Excel с обеими шкалами;
- графики числовых и логических выражений с переключаемой шкалой времени:
  реальное время компьютера с отладчиком или время контроллера; обе шкалы
  привязываются к миллисекундному счётчику PAC в начале сессии;
- вычисляемые счётчики серий импульсов: задаются имя, Lua-выражение
  считаемого датчика и его целевое значение, выражение ведомого датчика
  и его целевое значение. Первый импульс ведомого датчика фиксирует число
  импульсов считаемого датчика и начинает новый подсчёт. Результат доступен
  в дереве, истории, Excel и на графике;
- автоматическое переподключение по флажку «Переподключаться»: после обрыва
  связи или неудачной попытки подключение повторяется с нарастающей паузой —
  через 1 секунду, затем на 5 секунд дольше после каждой неудачи, но не чаще
  одного раза в 60 секунд; успешное подключение или ручное отключение
  сбрасывает паузу до начальной;
- интервал опроса от 100 до 9000 мс;
- долгосрочная клиентская история: 5000 точек на выражение по умолчанию,
  лимит настраивается в окне программы;
- настраиваемое окно графика в секундах и автопрокрутка последних N секунд;
- накопительные Min, Max, среднее и медиана для каждого выражения
  за всё время наблюдения;
- разовое вычисление Lua-выражения с консолью результатов: вывод
  переносится по ширине окна, история запросов и ошибок сохраняется
  в поле с прокруткой и не расширяет окно;
- вкладка «Переменные» с обзором глобальных и объектных таблиц в виде
  дерева: ручная загрузка корня и обновление ветвей, ленивое раскрытие
  и постраничная выдача по 128 записей, просмотр выбранной переменной;
- добавление выбранных переменных в автоматически обновляемый список
  наблюдения флажком «Наблюдать» (учитывается общий лимит 16 выражений);
- редактирование скалярных переменных без вызова функций — с явным
  диалогом подтверждения и перечитыванием записанного значения;
- выполнение команд контроллера из каждой вкладки с подтверждением перед
  отправкой: принудительное сохранение параметров, перезагрузка ограничений,
  сброс параметров и очистка кода результата;
- отдельная вкладка сообщений с системными логами, ошибками `error_manager`
  и событиями `set_err_msg` для каждой активной сессии;
- сохранение и загрузка адреса, интервала, лимита, окна отображения, выражений,
  флагов истории, настроек линий, счётчиков, журнала сообщений и ошибок,
  выбранной шкалы времени, автоматического переподключения
  и полученной истории;
- периодическое логирование сессии в каждой вкладке: полный снимок сессии
  сохраняется в файл с меткой времени в выбранном каталоге (по умолчанию
  каждые 60 минут); после каждой успешной записи история графиков
  очищается и начинается новый сегмент.

Счётчик добавляется кнопкой «Счётчик импульсов…». Значения вводятся как JSON:
`1`, `true`, `false` или строка в кавычках. Подсчёт начинается с первого
известного состояния сигналов после добавления; уже прошедшие импульсы не
восстанавливаются. Исходные выражения добавляются в опрос автоматически.
График удерживает результат последней завершённой серии; одинаковые итоги
(`10, 10, 10`) сохраняются отдельными точками истории. До первого результата
показывается ожидание. Остальные импульсы ведомого датчика не создают нули.
Для двух датчиков создайте два счётчика, поменяв считаемый и ведомый датчики
местами. Значения задаются без визуального сдвига по Y. Порога сброса нет:
серия из 11 импульсов сохраняется как 11.

Сервер хранит короткий кеш последних 64 изменений каждого выражения и последних 64
сообщений. Клиент объединяет ответы сервера без повторов и независимо хранит
выбранный объём истории для долгосрочного отображения.

Клиент получает величины и сообщения одним запросом `POLL` (команда 9),
который требует обновлённого контроллера. Сервер и отладчики обслуживаются
в чередующихся циклах PAC. Неполный TCP-пакет ожидает следующего цикла.
Команды контроллера передаются отдельным запросом (команда 10) только для
действующей сессии. Для принудительного сохранения ответ означает постановку
снимка в очередь; результат фоновой записи приходит позднее в журнале.

Для перезагрузки одного объекта разместите актуальный `main.objects.lua`
в пути проекта контроллера (`--path`). Из таблицы `init_tech_objects_modes()`
выбирается элемент `[N]`; отдельный файл объекта не требуется.
В строке «Объект» обновите список, выберите `OBJECTN` в простое
и нажмите «Перезагрузить объект». После подтверждения клиент показывает
результат или причину отказа; передача файла на контроллер выполняется отдельно.
Список загружается командой 11, перезагрузка — командой 10 с кодом `1030000+N`.
Нужны обновлённое ядро и `sys.objects.lua` версии 9. Можно менять шаги и
действия, сохраняя схему параметров и состав операций; подробные условия —
в [описании горячей перезагрузки](../../docs/hot_reload_review.md).

Вкладка «Переменные» показывает содержимое Lua-таблиц и объектов
контроллера в виде дерева (команды 12/13 протокола, нужно обновлённое ядро;
старое ядро сообщает об отсутствии поддержки, остальные функции при этом
работают). Корень задаётся выражением — по умолчанию `_G`, допустимы
`OBJECT1`, `OBJECTS[1]` и другие читаемые выражения. Загрузка выполняется
только кнопкой «Загрузить», ветви раскрываются лениво одним запросом,
страницы догружаются узлом «… ещё», а «Обновить» заново читает
выбранную ветвь или корень — периодического опроса дерева нет. Дочерние
узлы таблиц и унаследованные через `__index` поля раскрываются так же;
методы отображаются, но никогда не вызываются. Флажок «Наблюдать» у
скалярной переменной добавляет её выражение в обычный список наблюдения
(не более 16); снятие флажка удаляет только выражения, добавленные из
браузера, — наблюдаемые вручную выражения сохраняются.

Кнопка «Изменить значение…» и двойной щелчок по значению открывают
редактирование записываемого скалярного поля: выбирается тип (`number`,
`boolean`, `string`, `nil`) и вводится значение — строки передаются
контроллеру как сырые данные, а не как Lua-код. Перед каждой записью
показывается подтверждение с адресом контроллера, целью и новым
значением; ответ по умолчанию — «Нет». Запись `nil` удаляет поле —
действие помечается в диалоге как деструктивное. После успешной записи
отображается фактически перечитанное значение. Учтите, что управляющая
логика контроллера выполняется каждый цикл и может перезаписать
изменённое значение на следующем цикле.

Новая вкладка создаётся кнопкой `+` или `Ctrl+T`. Каждая вкладка хранит
собственное подключение, список выражений, статистику и историю.
`Сессия → Открыть` (`Ctrl+O`) загружает сохранённую сессию в новую
вкладку; `Ctrl+S` сохраняет текущую, а `Ctrl+W` её закрывает.

Флажок «Логирование» включает периодическое сохранение сессии: каждый
интервал (по умолчанию 60 минут) в выбранный каталог пишется новый файл
`*.ptlua.json` с меткой времени — такой же полный снимок, как при `Ctrl+S`.
История графиков, статистика и счётчики импульсов очищаются только после
успешной записи, и накопление начинает новый сегмент. При ошибке записи
логирование останавливается, а накопленная история сохраняется.

## Lua-код и setter наблюдаемого выражения

Кнопка «Выполнить Lua…» открывает многострочный редактор для однократного
выполнения Lua-кода на подключённом контроллере. Например:

```lua
LINE1V1:set_value(1)
return LINE1V1:get_value()
```

В редакторе Lua-кода **Tab** дополняет имена из уже загруженного дерева
на вкладке «Переменные». Единственный вариант вставляется сразу; при нескольких
вариантах появляется список: выбор стрелками, вставка по **Tab** или **Enter**,
закрытие по **Esc**. Поддерживаются глобальные имена, поля через `.` и методы
через `:`, например `LINE1V1:ge` → `LINE1V1:get_value`. Для дополнения полей
и методов сначала раскройте ветку объекта. Дополнение не запрашивает контроллер
и не выполняет Lua; без совпадений и внутри строк/комментариев Tab вставляет
обычную табуляцию. Регистр имён учитывается, как в Lua.

Первое возвращённое значение или ошибка видны в окне выполнения и в консоли
результатов основной вкладки. Без `return` результат — `nil`.
Нужно обновлённое ядро с командой 14; старое ядро выдаёт понятную ошибку.

Для записи через функцию добавьте `LINE1V1:get_value()` в наблюдение и
раскройте строку выражения. Заполните:

- **Setter:** `LINE1V1:set_value(<newvalue>)`;
- **Допустимые значения:** `(0;1;2)`;
- **Новое значение:** `1`, затем нажмите «Установить…».

Перед отправкой показываются адрес контроллера, getter, setter и новое
значение. Setter выполняется один раз, после него вызывается getter:
в консоли показывается фактическое значение, а наблюдение обновляется.
Функция может скорректировать переданное значение, поэтому результат не
обязательно равен введённому. Сдвиг линии графика на запись не влияет.

Значения вводятся как JSON-скаляры: конечное число, `true`, `false` или
строка в двойных кавычках. Список разделяется `;`, внешние скобки необязательны:
`(true;false)`, `("auto";"manual")`, `(-1;0;0.5;1)`.
Пустое поле ограничений разрешает любой из этих скаляров; `null` не допускается.
Число `1`, строка `"1"` и `true` различаются. Значение не интерпретируется
как Lua-код. Проверка списка выполняется в клиенте и в отправляемом Lua-блоке
до вызова setter. Это настройка отладчика, а не постоянное ограничение
контроллера: произвольный код из консоли не ограничен этим списком.

Getter и setter работают в текущем Lua-состоянии контроллера. Ошибка выполнения
не откатывает уже сделанные изменения, включая случай ошибки getter после
успешного setter. Команды не повторяются автоматически при потере ответа
или переподключении. После ошибки связи клиент закрывает соединение и сообщает,
что результат выполнения неизвестен: запись могла уже произойти. Если подключение
изменилось во время диалога подтверждения, запрос отменяется — подтвердите его
заново. Код выполняется синхронно: длительный или бесконечный цикл задержит цикл PAC.

Setter и ограничения сохраняются вместе с сессией, включая периодические
снимки. Загрузка сессии и подключение ничего не записывают; поле нового
значения остаётся пустым. Старые файлы сессий открываются без setter.

## Запуск из исходников

```powershell
uv sync --group dev
uv run ptusa-lua-debugger
```

## Проверка

```powershell
uv run pytest
```

## Сборка Windows EXE

```powershell
.\build.ps1
```

Результат: `dist\PtusaLuaDebugger.exe`.

Для создания установщика установите Inno Setup 6, добавьте `ISCC.exe` в
`PATH` и выполните:

```powershell
.\build.ps1 -Installer
```

Результат: `installer\PtusaLuaDebuggerSetup.exe`.
