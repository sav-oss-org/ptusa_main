# Горячая перезагрузка отдельных объектов

Ядро требует `sys.objects.lua` версии **9** из подмодуля
`demo_projects/T1-PLCnext-Demo/sys`. Текущая выпущенная версия — 8;
версия 9 с горячей перезагрузкой находится в процессе тестирования.
Обновлять ядро и системный скрипт нужно совместно.

## Использование

1. Разместите актуальный `main.objects.lua` в пути проекта контроллера (`--path`).
   Отдельные `objects/obj_N.lua` больше не используются.
   `N` — порядковый номер в таблице `init_tech_objects_modes()`, соответствующий
   `OBJECTN`, от 1 до 999; это не поле `n` описания объекта.
2. Файл целиком выполняется в изолированном окружении, затем вызывается его
   `init_tech_objects_modes()` и выбирается только элемент `[N]`.
   Остальные работающие объекты не пересоздаются; глобальная функция
   `init_tech_objects_modes` работающей программы не заменяется.
   Доступны константы `operation`, `step`, `valve`, но нет доступа к глобальным
   объектам PAC, `require` и файловым операциям. Принимается исходный Lua-код
   без заданного лимита размера файла или числа Lua-инструкций.
   Загрузка и выполнение синхронные: длительное выполнение задерживает цикл
   PAC, а бесконечный цикл блокирует его. Размер ограничен доступной памятью.
   Отсутствие функции, таблицы или выбранного описания приводит к отказу.
3. В отладчике подключитесь к контроллеру, обновите список объектов,
   выберите объект в простое и нажмите «Перезагрузить объект».
   Отладчик отправляет команду; файл нужно заранее разместить на контроллере.
   Альтернативный вызов: `SYSTEM:set_cmd("CMD", 0, 1030000 + N)`.

Можно менять состояния, шаги и действия существующих операций, переходы,
ссылки на существующие устройства и параметры. Имя/номер/тип объекта,
таймеры, схема и порядок параметров, число/порядок/имена операций и остальные
метаданные должны совпадать с описанием холодного старта. Для их изменения
нужен холодный перезапуск. Объект с активной операцией RUN, PAUSE или STOP
перезагружать нельзя; состояние повторно проверяется перед заменой.
Вызов из обработчика запуска/останова или текущего расчёта операций также
отклоняется, чтобы не удалить операции, которые ещё используются этим вызовом.

## Гарантии и результаты

Новый менеджер операций строится отдельно и устанавливается только после
успешной проверки. Сам `tech_object`, Lua-обёртка, параметры, их адреса в NVRAM,
таймеры, регистрация в коммуникаторе и реестре ошибок сохраняются. Повторные
перезагрузки не резервируют новые области параметров. Ошибка загрузки,
проверки или построения оставляет прежние операции действующими.

Если Lua-код хранит ссылки на менеджер операций, операцию, состояние, шаг
или действие, reload отклоняется: иначе после удаления старых операций
ссылки стали бы недействительными. Освободите сохранённые ссылки и повторите
команду; ссылки на объект, параметры и таймеры можно сохранять.

| Результат | Значение |
|---:|---|
| 0 | Перезагрузка выполнена |
| -1 | Объект не найден |
| -2 | Объект не в простое или его операции используются текущим вызовом |
| -3 | Ошибка файла, несовместимое описание или ошибка Lua |
| -4 | Lua удерживает ссылки на прежние операции/шаги/действия |

Результат записывается в `SYSTEM.CMD`, текст — в `SYSTEM.CMD_ANSWER`.
Сервис отладчика возвращает результат синхронно и передаёт подробную ошибку.
Перезагрузка не вызывает повторно `user_init`, `init_params` или подключение
пользовательских модулей и не заменяет их функции.

Команды PHOENIX Modbus/UDP сохраняют номера **301** (включить) и
**302** (выключить).

## Проверки

`test/hot_reload_tests.cpp` выполняет реальный `sys.objects.lua` с Lua/tolua
и C++-объектами. Проверяются повторная перезагрузка, неизменность адресов и
значений параметров, отсутствие новых резервирований NVRAM, откат при ошибке,
занятые объекты, сохранённые Lua-ссылки, стек Lua и команды отладчика.
Отдельно проверяется отказ при попытке reload из Lua-обработчика запуска.
Для общего файла проверяются выбор по порядковому индексу, перезагрузка
второго объекта при работающем первом, изоляция глобальных переменных,
отсутствие функции/описания, загрузка файла больше 1 MiB и выполнение файла
и функции описаний с числом инструкций выше прежнего лимита.
Тесты клиента проверяют выбор объекта, блокировку кнопок, обновление списка,
отключение, ошибки и формат протокола. Испытания проводятся локально без I/O;
проверка на физическом контроллере в эти тесты не входит.

На локальном `ptusa_main --no_io --opc off` через TCP-клиент также проверены:
перезагрузка первого объекта при работающем втором, обновление шагов,
отказ для занятого объекта и неверного модуля, восстановление после ошибки.
После reload параметр изменён, сохранён командой 102 и успешно восстановлен
после холодного перезапуска процесса.
