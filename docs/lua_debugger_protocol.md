# Lua-отладчик

Отладчик доступен через штатный TCP-сервер контроллера на порту `10000` как
сервис `2`. Версия общего протокола с поддержкой сессий отладчика — `106`.

## Кадр запроса

Используется обычный одиночный кадр протокола:

| Смещение | Размер | Значение |
|---:|---:|---|
| 0 | 1 | `'s'` |
| 1 | 1 | номер сервиса: `2` |
| 2 | 1 | тип кадра: `1` |
| 3 | 1 | идентификатор пакета, не равный `0` |
| 4 | 2 | длина payload, big-endian |
| 6 | N | payload отладчика |

Первый байт payload — команда. Команда создания сессии не имеет параметров.
Для остальных команд далее передаётся UTF-8 строка в формате:

```text
<session_id>\n<данные команды>
```

Ответ возвращается штатным кадром подтверждения с zero-terminated JSON в
payload.

## Сессия

После установления TCP-соединения клиент отправляет команду `1`. Сервер
создаёт независимую сессию и отвечает:

```json
{"ok":true,"session_id":"0123456789abcdef","timeout_ms":10000,"controller_time_unix_ms":1789123456789,"controller_time_millisec":12500}
```

Любой корректный запрос с этим идентификатором обновляет время активности.
Если запросов нет более 10 секунд, сессия удаляется в очередном цикле PAC,
скомпилированные Lua-выражения освобождаются. Одновременно поддерживается до 16
сессий. Клиент может завершить сессию явно командой `6`.

Поля `controller_time_unix_ms` и `controller_time_millisec` образуют временной
якорь, снятый контроллером при создании сессии. Первое поле содержит системное
время контроллера в миллисекундах Unix, второе — соответствующее ему значение
`get_millisec()`. Время точки вычисляется как `controller_time_unix_ms +
((time_ms - controller_time_millisec) modulo 2^32)`, поэтому шкала сохраняет
реальное время контроллера и корректно переживает переполнение счётчика.

## Команды

| Код | Команда | Данные после `session_id` |
|---:|---|---|
| 1 | Создать сессию | Не передаются |
| 2 | Вычислить выражение | Одно Lua-выражение |
| 3 | Настроить графики | Lua-выражения, по одному на строку |
| 4 | Получить данные графиков | Не передаются |
| 5 | Очистить точки графиков | Не передаются |
| 6 | Завершить сессию | Не передаются |
| 7 | Продлить сессию | Не передаются |
| 8 | Получить сообщения | Не передаются |
| 9 | Получить графики и сообщения | Не передаются |
| 10 | Выполнить команду контроллера | Целочисленный код команды |
| 11 | Список объектов для перезагрузки | Не передаются |
| 12 | Обзор переменных | `<выражение>\n<смещение>` |
| 13 | Записать переменную | `<выражение>\n<тип>\n<значение>` |

Команда `10` (`CMD_EXEC_CONTROLLER_COMMAND`) принимает
идентификаторы `301` (включить Modbus/UDP для PHOENIX) и `302` (вернуть TCP).
Для горячей перезагрузки отдельного объекта она принимает `1030000+N`,
где `N` — порядковый номер объекта, 1–999. Ответ синхронный:

```json
{"ok":true,"command":1030001,"object":1,"result":0,"queued":false,"message":"Object 1 reloaded."}
```

При отказе `ok=false`, `result` содержит отрицательный код, а `error` —
подробную причину. Другие команды сохраняют прежний формат ответа.
Условия перезагрузки описаны в [hot_reload_review.md](hot_reload_review.md).

Команда `11` (`CMD_GET_RELOAD_OBJECTS`) возвращает зарегистрированные объекты
с номерами 1–999 и текущим состоянием:

```json
{"ok":true,"objects":[{"id":1,"name":"Tank","lua_name":"OBJECT1","idle":true}]}
```

`idle` — состояние на момент запроса. Контроллер повторно проверяет его при
выполнении команды перезагрузки. Список не проверяет наличие `main.objects.lua`.

Команда `3` атомарно заменяет список выражений только в указанной сессии.
Поддерживается до 16 выражений длиной до 1024 байт. Они компилируются при
настройке, выполняются после основной Lua-логики в каждом цикле PAC, и новая
точка сохраняется только при изменении значения или состояния ошибки. Для
каждого выражения хранится до 128 последних изменений.

Пример ответа команды `2`:

```json
{"ok":true,"type":"number","value":42}
```

Пример ответа команды `4`:

```json
{
  "ok": true,
  "server_time_ms": 12500,
  "series": [
    {
      "expression": "TE1:get_value()",
      "samples": [
        {"time_ms":12345,"ok":true,"type":"number","value":20.5}
      ]
    }
  ]
}
```

`server_time_ms` и `time_ms` получены из системного миллисекундного счётчика
PAC и циклически переполняются. Клиент переводит их во время контроллера по
якорю, полученному при создании сессии. Для графиков предназначены числовые и
логические выражения. Строковые значения также поддерживаются. Для таблиц,
функций и userdata возвращается имя типа, например `"<table>"`; нужное поле
следует указать непосредственно в выражении.

## Обзор переменных

Команда `12` (`CMD_BROWSE_VARIABLES`) доступна в ядре начиная с версии,
поддерживающей команды 12/13; старое ядро отвечает `Unknown command`
(без номера команды).
Параметры после `session_id` — корневое выражение и десятичное смещение
страницы:

```text
<выражение>\n<смещение>
```

Корневое выражение вычисляется один раз под `lua_pcall`, как в команде `2`.
Если результат — таблица или userdata, команда возвращает страницу до 128
полей с детерминированным лексикографическим порядком по отображаемому
имени `name` (при равных именах — по порядковому номеру типа ключа,
затем по `expression`), устойчивым между страницами, пока таблица не
изменилась. Скалярный корень возвращает `entries` пустым и `value` с
значением. Ответ:

```json
{
  "ok": true,
  "expression": "_G",
  "type": "table",
  "entries": [
    {
      "name": "OBJECT1",
      "expression": "_G[\"OBJECT1\"]",
      "type": "table",
      "value": "<table>",
      "expandable": true,
      "writable": false
    }
  ],
  "offset": 0,
  "next_offset": 128,
  "truncated": false
}
```

`next_offset` — позиция следующей страницы либо `null`, когда выдано всё.
Страница ограничена также размером TCP-ответа: не более 65535 байт
вместе с завершающим NUL. Поэтому она может содержать менее 128 полей;
для продолжения используется возвращённый `next_offset`.
`truncated=true` означает, что часть перечисления не показана:
сканирование остановлено по пределу 4096 кандидатов, имя усечено либо
достигнута глубина наследования 16 уровней. Имена записей ограничены
512 байтами, текстовые значения — предпросмотром 256 байт. Флаги
независимы: `truncated` относится к перечислению в целом, а
`value_truncated` — к конкретному предпросмотру значения (в том числе
корневого `value`). Такое значение является предпросмотром — клиент не
подставляет его как полное значение при редактировании. Если строка
содержит байты, не являющиеся корректным UTF-8, предпросмотр показывает
их десятичными escape-последовательностями и дополнительно помечается
`"value_lossy":true`: показанный текст не совпадает с исходными данными
и не может быть записан обратно из предпросмотра — требуется явный ввод
нового значения. Пути длиннее 1024 байт не адресуются и
возвращаются с пустым `expression`. Ошибки чтения полей (например,
геттеров свойств) возвращаются в `value` записи с пометкой об ошибке, а не
прерывают обзор; методы никогда не вызываются, а геттеры свойств
вызываются только для выдаваемой страницы после завершения перечисления.
Унаследованные поля подхватываются по цепочке табличных `__index`
(не более 16 уровней, циклы исключены); вызов функций `__index` для
перечисления не выполняется. У userdata перечисляются таблица-окружение
(peer-таблица), поля методов из метатаблиц и свойства `.get`/`.set`;
индексы внутренних индексированных массивов C++ не перечисляются и не
подделываются.

Для таблиц и userdata корень ответа и записи содержат необязательное
поле `object_id` — непрозрачную строку идентичности объекта в текущем
состоянии Lua. Клиент сравнивает её с предками текущей ветки (включая
корень) и показывает совпадение как циклическую ссылку без раскрытия.
Совпадения в соседних ветках не ограничивают навигацию. Идентификаторы
не предназначены для хранения между сессиями; дерево является снимком,
при изменении объектов его следует загрузить заново. Старые серверы без
`object_id` поддерживаются, но не позволяют распознавать циклы.

`expression` записи — готовый дочерний путь для последующего обзора. Он
пригоден для записи только у назначаемых целей (`writable=true`): глобальные
и вложенные скалярные поля таблиц, а также свойства userdata с сеттером.

## Запись переменной

Команда `13` (`CMD_SET_VARIABLE`) принимает параметры:

```text
<выражение-цель>\n<тип>\n<значение>
```

Цель должна быть корректным присваиваемым выражением: корневой идентификатор,
далее `.имя` или `["строка"]` / `[число]` / `[true|false]`. Вызовы функций,
операторы и произвольные выражения отвергаются синтаксическим разбором до
обращения к Lua. Поддерживаемые типы значения: `number` (конечное
десятичное/экспоненциальное число), `boolean` (строго `true`/`false`),
`string` (сырые UTF-8 данные, не Lua-код — кавычки и переводы строк передаются
как есть) и `nil` (только пустое значение). Правая часть никогда не
подставляется в исходный код — значение передаётся в присваивающее замыкание
как типизированный аргумент.

Цель должна существовать и быть скалярной в момент записи: запись в
отсутствующее, табличное или функциональное поле отвергается. Смена типа
между скалярными типами разрешена. Свойства userdata записываются только
при наличии сеттера; `nil` для свойств не допускается.

**Внимание:** запись `nil` удаляет поле таблицы или глобальную переменную —
действие деструктивно и требует подтверждения в клиенте. Любая запись
выполняется в живом цикле PAC: управляющая логика может перезаписать
изменённое значение уже в следующем цикле.

Ответ содержит фактически прочитанное после записи значение (числовые
значения — JSON-числа, строки длиннее 256 байт помечаются
`"value_truncated":true`, строки с не-UTF-8 байтами — `"value_lossy":true`):

```json
{"ok":true,"expression":"OBJECT1.par","type":"number","value":42.5}
```

Ошибки (некорректная цель, неправильный тип значения, ошибка сеттера и т. п.)
возвращаются как `{"ok":false,"error":"..."}` без разрыва сессии. Все пути
обработки команд 12/13 сохраняют вершину стека Lua.

## Выполнение Lua-кода

Команда `14` (`CMD_EXECUTE`) принимает UTF-8 Lua-блок после строки
идентификатора сессии. Максимальная длина кода — 16384 байта. В отличие от
команды `2`, блок не оборачивается в `return (...)`: допустимы присваивания,
локальные переменные, несколько строк и явный `return`.

```lua
LINE1V1:set_value(1)
return LINE1V1:get_value()
```

Ответ имеет формат команды вычисления выражения:

```json
{"ok":true,"type":"number","value":1}
```

Возвращается только первый результат, без `return` — `nil` / JSON `null`.
Синтаксические ошибки и ошибки выполнения возвращаются как
`{"ok":false,"type":"error","error":"..."}`. Стек Lua восстанавливается
при успехе и ошибке. Нужна действующая сессия; выполнение синхронное, в том
же потоке и Lua-состоянии, что и вычисление выражений. Уже выполненные
изменения не откатываются при ошибке, лимита времени исполнения нет.

Windows-клиент использует эту команду также для setter наблюдаемого getter.
Он проверяет введённый JSON-скаляр по списку допустимых значений и формирует
блок с проверкой списка перед вызовом setter, затем возвращает getter.
Числа и boolean записываются Lua-литералами, строки — десятичными escape
последовательностями UTF-8 байтов, совместимыми с Lua 5.1. Setter и ограничения
хранятся в файле клиентской сессии, а не в постоянной конфигурации PAC.
Клиент не повторяет команду автоматически после ошибки связи.
