## Как собрать проект ##

Вы можете клонировать репозиторий при помощи следующей команды:
`git clone --recurse-submodules
https://github.com/sav-oss-org/ptusa_main.git`

Или, если вы клонировали проект без инициализированных и обновленных
подмодулей, попробуйте следующее:
`git submodule update --init --recursive`

### win ###

Требования:

+ Qt Creator

В Qt вы можете открыть файл CMakeLists.txt клонированного репозитория.

Или клонировать репозиторий используя Qt:
    Добавить -> Импортировать проект -> Клонирование Git
указать ссылку на репозиторий и поставить галочку для рекурсивного
клонирования.

+ Microsoft Visual Studio Community 2022

Перед запуском проекта необходимо убедиться в том, что у вас установлен C++
CMake tools for Windows.
Средства C++ CMake для Windows устанавливаются с помощью:

`Visual Studio Installer -> Разработка классических приложений на C++ ->
Средства CMake C++ для Windows`

Подробную информацию по установке можно получить
[здесь](https://docs.microsoft.com/ru-ru/cpp/build/cmake-projects-in-visual-studio?view=msvc-160).
Версия CMake, необходимая для сборки: 3.31 и выше.

После этого вы должны открыть (в Visual Studio) корневой каталог. Таким
образом, вы получаете проект на основе CMake. Если после запуска возникла
ошибка, то следует очистить кэш CMake: `Проект -> Удалить кэш и выполнить
перенастройку`.

### Linux ###

Eclipse IDE с проектом на базе CMake в Linux.

## Использование набора инструментов PLCnext Technology C++ для ОС Windows ##

Загрузите последние версии с веб-сайта Phoenix Contact
<https://www.phoenixcontact.com/products> (например, из области **AXC F 2152**)
`PLCnext Control firmware` (текущая 2023.0 LTS) и `sdk для
Windows 64 bit` (текущая 2022.0.4 LTS) , в разделе Загрузки->Программное
обеспечение $-$ <http://www.phoenixcontact.com/qr/2404267/softw>.

Перейдите в папку, где находятся загрузки (типичный путь
`%userprofile%/Downloads`), распакуйте архив
(`SDK_2021.9_Windows_AXC_F_2152.tar.xz.zip`).

### Установка (обновление) SDK ###

Перейдите в папку, в которую ранее был распакован архив, вызовите CLI в
консоли, используя следующую команду:

```ps
plcncli.exe install sdk –d [путь установки] –p [путь к архивному файлу]
```

>Если вы устанавливаете несколько SDK, Phoenix Contact рекомендует использовать
структуру папок "целевое имя/версия встроенного ПО".

Также ваш путь установки должен совпадать с путем в CMake.

Например:

```ps
plcncli.exe install sdk -d C:\CLI\sdks\AXCF2152\2022_0 \ -p pxc-glibc-x86_64-mingw32-axcf2152-image-mingw-cortexa9t2hf-neon-axcf2152-toolchain-2022.0.tar.xz
```

>SDK указан для контроллера. Полный список контроллеров можно найти на сайте
PHOENIX CONTACT ([Главная страница > Продукция > ПЛК и системы ввода-вывода >
Управление PLCnext > Список продуктов Технология PLCnext
components](https://www.phoenixcontact.com/online/portal/pi?1dmy&urile=wcm%3apath%3a/pien/web/main/products/list_pages/PLCnext_technology_components_P-21-14-01/f77f0eb0-2a70-40c3-8679-7df2450e26db))

## Как запустить проект ##

Для запуска демо проекта вы должны использовать эту команду:

### windows ###

+ После сборки и развертывания *`windows-default`* конфигурации cmake:

```cmd
    bin\install\windows-default\Release\ptusa_main.exe ^
    --path demo_projects/T1-PLCnext-Demo/ ^
    --sys_path demo_projects/T1-PLCnext-Demo/sys/ ^
    --debug ^
    demo_projects/T1-PLCnext-Demo/main.plua
```

+ Запуск проекта в Microsoft Visual Studio Community 2022: `Выбрать элемент
запуска -> ptusa_main.exe`.

### Необязательный конфигурационный файл standalone-приложения ###

Настройки запуска можно хранить в UTF-8 файле с парами `ключ=значение`.
Файл подключается только явно через `--config` (или `-c`):

```cmd
ptusa_main.exe --config ptusa_main.ini
ptusa_main.exe --config ptusa_main.ini --sleep_time=0.5 --min_cycle_time=7
```

Пример: [ptusa_main.ini.example](../../misc/ptusa_main.ini.example).
Ключи совпадают с полными именами консольных параметров: `script`, `path`,
`sys_path`, `extra_paths`, `debug`, `rcrc`, `port`, `opc`, `no_io`,
`read_only_io`, `phoenix_modbus_udp`, `phoenix_modbus_udp_timeout_ms`,
`sleep_time`, `min_cycle_time`. Логические значения задаются как `true`/`false`.
`rcrc=true` сбрасывает сохраненные параметры при каждом запуске.

Пустые строки и строки, начинающиеся с `#` или `;`, игнорируются.
Значения можно заключать в одинарные или двойные кавычки, например
`path="D:/Projects/Мой проект"`. Секции и комментарии после значений не
используются. Все относительные пути отсчитываются от рабочего каталога
запуска, включая путь `script`, который можно также задать позиционно.

Приоритет: параметры командной строки, затем файл, затем значения по
умолчанию. Без `--config` приложение работает с консольными параметрами.
Если явно указанный файл не найден, содержит неизвестный или повторный ключ,
ошибочное значение либо некорректную строку, запуск завершается с ошибкой.

`sleep_time` задает основную паузу в каждом цикле: **0.1–10 мс**, по умолчанию
**1 мс**. `min_cycle_time` задает минимальную длительность всего цикла вместе
с основной паузой: **0–20 мс**, по умолчанию **5 мс**. Если цикл выполняется
быстрее, приложение вызывает sleep на оставшееся время; `0` отключает эту
добавочную паузу. Дробная часть задается через точку. Фактическое время
ожидания зависит от планировщика ОС и может превышать заданное.
